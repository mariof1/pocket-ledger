# Pocket Ledger audit — 15 September 2026

Scope: Flask API and SQLite schema, authentication and profile isolation, budgeting records, calculator math and lender criteria, desktop screens, and a 390 × 844 mobile viewport. The latest filled-screen checks used a disposable account and database; existing account records were left untouched.

## Findings resolved

| Area | Finding and change |
| --- | --- |
| Authentication | A copied signed cookie remained usable after sign-out. Server-side session tokens now revoke it. Password change in Profiles & settings revokes other sessions; an owner-run `reset_password.py` command provides recovery without placing a new password on the command line. |
| Data scale | `/api/data` returned the entire transaction history. It now returns monthly totals, a six-month chart, spending groups, and five recent entries. Transactions have a separate 50-row API with server-side search, kind filters, and paging. The browser discards outdated paging responses. |
| Categories | A bill category typed once could not be selected again. Per-profile saved categories now appear in bill, transaction, and budget suggestions, survive bill deletion, and deduplicate case-insensitively. |
| Remote access | A non-loopback `LEDGER_HOST` could expose credentials and cookies over plain HTTP. The server now refuses that bind. Remote access requires an HTTPS reverse proxy to the loopback server with `LEDGER_HTTPS=1` for Secure cookies; HSTS is sent in that mode. |
| Lender guide | Santander's 95% LTV house screen used flat-only caps. The calculator asks for property type and applies the corresponding published limits. Mortgage inputs and outputs are GBP even when a different profile currency is selected. After 45 days from its criteria review date, the guide warns that published caps need rechecking and stops claiming a loan is within one. |
| Visual and accessibility | The empty overview chart left a large blank panel; it now explains how to populate the chart. Bills and transactions use readable mobile cards. The mobile menu has a backdrop, hides closed navigation from assistive technology, and closes on Escape or backdrop click. The settings password panel and mortgage modes fit the phone viewport. |
| Input and dependency checks | Default month and transaction dates use the browser's local date. Invalid year 0000 and non-finite calculator outputs are rejected. Flask is pinned to the reviewed 3.1.3 maintenance release. |
| Populated phone screens | A filled Overview squeezed recent transactions into a four-column table, and months without entries showed tiny chart bars. Recent activity now uses phone cards and zero-value bars are hidden. Filled Budgets, Savings goals, and Transactions also rendered clearly at 390 × 844. |
| Record validation | A fractional or Boolean bill day could be stored as a whole day, and malformed transaction notes could become stringified or silently truncated. Bill days now require a whole number; notes must be text of at most 200 characters. Transaction offsets outside the supported range return HTTP 400 rather than risking a server error. |
| Extreme mortgage inputs | Very large but finite income could produce an infinite published ceiling and a misleading cap match. The affordability guide now bounds price, income, take-home pay, and monthly costs before calculating lender comparisons. |
| Recurring bill planning | Bills now store a daily, weekly, two-week, four-week, monthly, three-month, or yearly frequency. Existing rows migrate to monthly. The server computes a rounded monthly average per bill and a per-profile total; Bills, Overview, and Budgets display these planning amounts separately from paid transactions. |
| Calendar commuting | Regular Bills now stores per-profile car or public transport plans, chosen commuting weekdays, exact leave dates or ranges, and optional regional UK bank-holiday exclusion. Car fuel uses imperial UK mpg and litres per gallon. The selected calendar month's commute cost joins the planning total in Bills, Overview, and Budgets; recorded spending remains transaction-only. Unavailable official holiday dates show a warning. |
| Responsive commute dialog | The scrolling modal could reopen partway down on a phone, hiding its heading and close button. It now scrolls to the top and focuses Close when opened. |
| Annual leave planning | Commuting can now use a whole yearly allowance instead of date entry. The month receives a share proportional to its selected commuting weekdays after optional bank holidays, so bank holidays are excluded separately. Annual and exact-date modes cannot be combined; existing plans upgrade as exact-date plans without altering their saved dates. The UI labels annual results as estimates. |

The additive upgrade retained existing bills, created an empty commuting table, and passed SQLite integrity and foreign-key checks. - A disposable annual-leave account entered 25 days per year and excluded England & Wales bank holidays. Annual-form edit and preview were checked in the browser.
- Before the live annual-leave migration, the database was backed up locally. The additive upgrade preserved existing bills and commuting plans in their existing fields; those plans default to exact-date mode. ## Limits of this audit

The lender guide covers selected published schemes from Nationwide, HSBC, and Santander, not every lender or every underwriting condition. Its review date is a snapshot; source links and the age warning help prevent an old cap from being treated as current. A lender's Decision or Agreement in Principle is needed for a personalised affordability decision. Password recovery requires the server owner to have console access. The 5,000-record timing is one local sample, not a sustained multi-user load test. HTTPS proxy configuration and exposure must be verified on the owner's network before remote use.

Criteria and maintenance sources checked: [Nationwide affordability](https://www.nationwide-intermediary.co.uk/lending-criteria/affordability), [Nationwide borrower types](https://www.nationwide-intermediary.co.uk/lending-criteria/borrower-types), [HSBC borrowing guidance](https://www.hsbc.co.uk/mortgages/how-much-can-i-borrow/), [Santander high-LTV products](https://www.santanderforintermediaries.co.uk/products/high-ltv-mortgages), [Santander residential criteria](https://www.santanderforintermediaries.co.uk/lending-criteria/residential-lending-criteria), and [Flask changes](https://flask.palletsprojects.com/en/stable/changes/).

Commuting holiday source checked: [GOV.UK bank holiday data](https://www.gov.uk/bank-holidays.json) and [GOV.UK employer leave guidance](https://www.gov.uk/bank-holidays).

## Follow-up audit — 15 September 2026

A second filled desktop review used an isolated account with 58 transactions, recurring bills, two commuting plans, budgets, goals and two currency-separated profiles. It covered Overview, Transactions search and paging, Budgets, Savings goals, bill occurrence review and import controls, Profiles & settings, mortgage payment and affordability modes, savings growth, and spending habit. The isolated account was also used for malformed API requests; all 13 sampled bad inputs returned 4xx rather than 500. The live unauthenticated data endpoint returned 401 with no-store, CSP and frame-denial headers. SQLite integrity and foreign-key checks passed. Existing account records were not changed by the screen review.

| Area | Finding and change |
| --- | --- |
| Actual spending dates | The transaction form allowed future expenses, and the overview counted them as already spent. New transactions now require today or an earlier date. Existing future-dated rows remain editable in the transaction list but are omitted from monthly actual totals, spending groups, recent activity and the six-month chart until their date arrives. Bill import already excludes future occurrences. |
| Transactions label | Search results displayed “1 records.” The count now uses the singular form for one result. |
| Bank-holiday outage | An unavailable GOV.UK endpoint could impose a three-second delay on every commute page load. A failed lookup now backs off for five minutes while keeping any cached dates and warning visible, then retries. |
| Mortgage source link | The old direct Santander criteria download stopped resolving. The guide now opens the current official residential criteria landing page. Published lender caps were rechecked against linked Nationwide, HSBC and Santander pages. |
| Runtime version | The local server was running with system Flask 3.1.1 despite the project's Flask 3.1.3 pin. It was restarted with the project virtual environment so the served app uses the reviewed maintenance release. |

The follow-up passed 22 Flask tests, 6 mortgage-guide tests, JavaScript syntax, Python compilation, malformed-input probes, and a populated desktop browser review. A live SQLite backup was taken before the server restart, with integrity and account-record counts checked afterward. Phone viewport checks from the earlier audit were not repeated for these follow-up changes. HTTPS reverse-proxy behavior remains untested on this owner's network; the app is currently bound to loopback.

## Pre-repository audit — 15 September 2026

The current server was checked for loopback binding, unauthenticated endpoint protection, account and profile separation, CSRF, cookie and response headers, transfer atomicity, recurring bill and commute totals, monthly aggregates, mortgage screens, SQLite integrity and foreign keys. The published lender links and maintenance dependency releases were rechecked. Populated desktop Overview, Bills, Transactions and Settings screens were reviewed in a separate browser tab without submitting forms. Previous 390 × 844 mobile checks are documented above; the phone viewport and HTTPS reverse proxy were not repeated in this pass.

An array or object supplied as an export bill frequency or commute bank-holiday region previously raised a server error during import. Both now return an input error; failed imports roll back the entire transaction. The regression suite passed 24 Flask tests and 6 mortgage-guide tests, along with Python compilation and JavaScript syntax. The live SQLite integrity and foreign-key checks passed. A file-inclusion review confirmed that Git ignores `instance/`, signing keys, database backups, the virtual environment and bytecode. No account records or credentials are in the planned commit.

The populated Savings goals screen showed a target date beside a much later completion estimate without explaining the gap. It now warns when the saved monthly pace misses the date, estimates the amount needed over the available months, and flags passed deadlines. The filled card was checked again in the browser. These are calendar-month planning estimates, since the app does not record a day of month for goal contributions.
